## 3. Findings

### F1 · P1 · blocking `V2_SSOT_FROZEN`
`a1-2-6-min-3-contradicts-a2-1-5-1a-gate-as-endpoint`

**A1 §2.6 규칙 MIN-3(신설)이 A2 §1.5.1a 를 정면으로 부정한다.**

A1:348-351 —

> `02` §7 은 gate 도달 시 즉시 종료를 요구한다. 그러므로 열거가 반환하는 것은 정확히
> "최소 길이의 **terminal** 경로"이며, gate 가 더 얕은 길이에서 발화하면 **그보다 깊은
> endpoint 경로는 열거되지 않는다.** 이 경우 `endpoint_reached = 0` 이고
> `MPFED` 는 `NULL` 이다(§1.5) — gate 길이를 MPFED 로 대입하지 않는다.

A1 §8(신설 행) —

> - gate 로 끊긴 관측의 terminal 길이를 `MPFED` 로 대입하는 것 — `NULL` 이다(규칙 MIN-3).

A2 §1.5.1a 규범표는 `FINANCIAL_ACTION_ENTRY`(로그인·인증 gate, 종류 확정) ·
`COMMUNICATION_ENTRY`(로그인 gate, 종류 확정)에서 **`endpoint_reached = 1` · `MPFED = 정수(m)`**
를 요구한다. 그 `m` 이 곧 gate 도달 terminal 길이다. **A1 §8 의 새 금지가 A2 §1.5.1a 의
의무를 금지한다.**

**범위 실측** — `A1 §2.6`(306~430행) 안에 `FINANCIAL_ACTION_ENTRY` · `COMMUNICATION_ENTRY` ·
`A2 §1.5.1a` · `E-5` · `E-6` · `archetype` 이 **한 번도 나오지 않는다**. MIN-3 이 인용한 `(§1.5)`
에는 예외 교차참조가 있으나, MIN-3 자신의 문장은 예외 없는 전칭이고 §8 의 금지는 무조건이다.

**왜 A2 우선으로 해소되지 않는가** — `A2 §0 3항` 권위표에서 **A1 = 8위, A2 = 9위**다.
A2 가 우선하는 것은 `A1 §0.3` / `A2 §0 4항` 관할표에 열거된 7개 절뿐이고 **`§2.6` 은 그 표에 없다.**
따라서 문면대로 읽으면 충돌이 **A1 쪽으로** 해소된다.

**왜 가드가 잡지 못하는가** — `§6.3` 의 E-6a·E-6b 가드는 **과승격 한 방향**만 실패시킨다.
`I-42`~`I-53` 어느 행도 *종류가 확정된 gate 가 실제로 승격되는가* 를 태우지 않는다
(`I-42`·`I-43` 은 `auth_gate_kind` 기록의 통과만 본다). 즉 MIN-3 대로 구현한 **과소승격**은
파이프라인이 침묵한다.

**결과** — 두 archetype 의 `MPFED` 가 구조적으로 다시 전부 `NULL` 이 되고
`00 §7` `ExcessDepth` 기준선 · `00 §11` archetype 별 Depth 분포 ·
`01 §10 mart_archetype_summary` 가 그 두 행에서 성립하지 않는다.
이것은 `68a715bb` 에서 CLOSED 판정한 `ssot-00-3-auth-gate-endpoint-contradicts-a2-1-5-1`
**의 명제 3 그 자체**이며, A2 에서 닫은 것이 A1 에서 열렸다.

**시정 요구**
1. MIN-3 에 두 archetype 예외를 넣고 `분기 규칙의 정본은 A2 §1.5.1a 규칙 E-5~E-10` 형태로
   위임한다 — `A1 §1.5` 가 이미 쓰는 형식 그대로.
2. `A1 §8` 의 신규 금지 행을 `두 archetype 의 확정된 gate 는 제외` 로 한정한다.
3. **`A1 §0.3` · `A2 §0 4항` 관할표에 `§2.6` 행을 추가한다** — §2.6 은 `endpoint_reached` ·
   `MPFED` · `endpoint_status` · `endpoint_status_detail` 이라는 A2 관할 값을 배정한다.
   양쪽 표를 같은 글자로 갱신해야 한다(한쪽만 갱신하면 그 자체가 drift).
4. (권고) `I-48` 의 대칭으로 *종류가 확정된 gate 는 승격되어야 한다* 는 과탐 회귀 주입 1건.

### F3 · P2 · blocking `V2_SSOT_FROZEN`
`rc-5-execution-authorization-reconciliation-row-still-scoped-to-recollection`

`§1.11.2` RC-5 보고 항목 `실행 인가 대조` 행(A2:1460)이 target 커밋에서 여전히

> control 이 인가한 실행 수 `E` · 원장 `EXECUTION` 레코드 수 · 제출된 **재수집** evidence run 수.

**같은 문서 안에서 어긋난다.**

**target 커밋에는 들어 있지 않다.** 시정 내용은 옳다 — 커밋되면 닫힌다.

### F4 · P2 · blocking `E001_V2`
`a1-6-2-lacks-evidence-run-id-derivation-binding`

C-2 담당이 미해결로 보고한 항목이다. **finding 이 맞다.**

`A1 §6.2`(evidence identity 정합)는 runner 가 읽는 정본이며 규약표에
`재수집은 새 evidence_run_id 를 만든다` 만 있다. `evidence_run_id` 는 이어서 `A1 §6.3` 의
`observation_id` 해시에 **자유 입력**으로 들어간다. C-2 의 (a) 채택으로 이제 **최초 run 을 포함한
모든 run** 의 `evidence_run_id` 가 `f(ledger_record_sha256, countersign_commit_sha, execution_index)`
의 상이어야 한다(A2 §1.11.2 RC-6 · 검사 A-6·A-7). A1 은 그 사실을 어디에도 적지 않는다
(`auth_gate_kind` 와 달리 `evidence_run_id` 는 A1 이 이미 쓰는 필드다).

**모순은 아니다** — A1 이 `자유 식별자다` 라고 단언하지 않고 침묵할 뿐이며, `§6.3` 가드가
fail-closed 라 잘못된 id 로 만든 evidence 는 제출 시점에 거부된다. 따라서
`V2_SSOT_FROZEN` 차단이 아니라 **E001_V2 차단**이다. 그러나 A1 만 보고 구현하는 runner 는
자유 id 를 만들어 E001 착수 시점에 전건 폐기하게 된다.

**시정 요구** — `A1 §6.2` 규약표에 바인딩 행 1건:
`evidence_run_id 는 자유 식별자가 아니다 — A2 §1.11.2 RC-6 유도식 f 의 상이며 최초 run 에도 적용된다`.

### F5 · P2 · blocking `P-B 산출물 검증`

같은 커밋이 `redirect_chain` · `target_url` 을 두 곳에 **서로 다른 Phase 로** 등재했다.

`§5.5` 의 라우팅도 그에 맞춰 두 행으로 나눈다.
