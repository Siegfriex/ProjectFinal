### 5.3 RC-6 검사 A-5 의 세 번째 조항은 실패할 수 없다 — **F6 (P2 비차단)**

A-5 는 세 조항이다 — ① `countersign_commit_sha` 가 control branch 에 있다,
② 그 tree 의 `control/state.json` 이 `prereg_commit_sha` 를 등재한다,
③ **그 커밋의 조상 중 이 run 의 evidence 를 담은 커밋이 없다.**

`control/landing-orchestrator` 와 수집이 일어나는 exec 계열 브랜치는 **분리된 계보**다

**③ 은 어떤 입력에서도 참이 되어 결코 실패할 수 없다.** ①②가 대외 서명 보호를 실제로 제공하므로
누수는 없고 **비차단**이다. 다만 `fail-closed 6검사` 라는 표기가 실효 검사 수를 과대표시한다.
ADV-C004-04 가 `dead argument` 로 잡은 것과 같은 형태이며, 순서 근거로 쓰려면
`prereg_commit_sha` 쪽 계보에서 부재를 확인하도록 다시 써야 한다(그 역할은 이미 A-3 이 한다).

1. **A2 141행이 관할표를 `A1 §0.3과 글자 그대로 동일` 이라고 쓴다.** routing 두 열은 7/7 동일이지만

   drift 가 아니다. `같은 목록` 으로 문면을 맞추면 기계 diff 로 검증하려는 독자의 오탐이 사라진다.

   싣고, `§6.3` 2203행도 `5필드` 라 적으며 6개 이름을 나열한다. V2-C004 에서 들어온 표기이며 표가 정본이다.
3. **control `observed_worktrees` 의 `아직 origin 에 push 돼 있지 않다`.** 그 커밋 시점 실측이고
   이후 `agent/landing-pa-shadow`·`agent/landing-pb-prework` 2개가 게시됐다. 시점 기술이라 결함이 아니다.
4. **A-5 의 `executor 는 control 브랜치를 쓰지 않는다`.** `05 §6`(executor self-approval 금지)과
   `EXECUTION_AUTHORITY §5`(역할↔브랜치 대응)에서 **따라 나오는 귀결**이며, 명시 금지문은 원본에 없다.
   A2 의 `재사용` 주장은 실질적으로 참이므로 EXC 등재까지 요구하지 않는다.
5. **A2 규칙 id 위생.** 표 행으로 정의된 규칙 id 85개 **중복 정의 0**.
