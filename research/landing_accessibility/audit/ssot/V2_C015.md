## 5. 비차단 발견 (P2 ×3) — verdict 의 blocking count 에 넣지 않는다

### P2-1 `gates-v2-ssot-frozen-narrative-stale-contradicts-recomputed-total`

`state.json.gates.V2_SSOT_FROZEN` 문자열이 여전히
`"NOT_ACHIEVED — … (1) open_blocking_total ≠ 0: 재계산 결과 3건 … (3) 두 감사 모두 PASS 아님: 최신 ssot verdict = FAIL"`
로 남아 있다. 같은 파일 `open_blocking_total.total = 0` · `gate_satisfied = true` · 두 감사 PASS 와
정면으로 어긋나는 **stale 서술**이다(V2-C010 시점 문면이 갱신되지 않았다).

- **비차단 사유**: 오차 방향이 실제보다 **보수적**이다 — 게이트를 열지 않고 닫는 쪽으로 틀렸다.
  게이트는 아직 ACHIEVED 로 **선언되지 않았고**, 따라서 §2.3 의 C-6 트리거 (i) 도 발동한 바 없다.
  authority-bypass 도 measurement-semantics 모순(측정 산식 자체의 모순)도 아니다.
- **조치**: 오케스트레이터가 `V2_SSOT_FROZEN` 을 선언할 때 이 문자열을 V2-C015 기준으로 재작성해야 한다.
  선언 전까지 방치해도 위험은 없다.

### P2-2 `phase-gates-2-exact-same-target-sha-not-literally-satisfied-across-the-two-audits`

`PHASE_GATES.md` L48 은 "adversarial 감사와 ssot 감사가 **exact same target SHA** 를 감사했다"를 요구한다.
현 상태는 adversarial `cd717661` @ control **`418a91a`** / 본 ssot 감사 @ control **`b969adb`** 로
**문언상 동일 SHA 가 아니다**(방향만 반대로 바뀌었다).

실질 위험은 **소멸돼 있다**. 실측:

```
418a91a:scripts/promote_landing_main.sh  blob a35e0bc6a70422e4df1baff0211f39fc6b4b7da0
b969adb:scripts/promote_landing_main.sh  blob a35e0bc6a70422e4df1baff0211f39fc6b4b7da0   → IDENTICAL
```

adversarial 이 감사한 **코드 표면이 `b969adb` 에서 바이트 동일**하고, `418a91a→b969adb` 델타는
