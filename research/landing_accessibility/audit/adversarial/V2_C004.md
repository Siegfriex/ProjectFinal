## 1. 결론

V2-C004는 `FAIL`이다. 네 건 모두 문구·표현·style 문제가 아니다.

1. 재수집 사전선언은 새 run 자신의 manifest 안에만 존재하여 결과를 본 뒤 시간을 소급해 만들 수 있다. 이는 optional stopping과 결론 선택을 다시 허용한다. `P1 / blocking`.
2. A1과 A2의 관할표가 서로 다르고 A1의 절 번호도 충돌한다. 서로 다른 구현자가 서로 다른 스키마 권위를 고를 수 있다. `P2 / blocking`.
3. 배너 allowlist 검사는 source-pack 파일에만 적용된다. A1 같은 repo-authored 권위문서에 위조 배너를 넣고 manifest를 갱신하면 verifier가 `PASS`한다. `P2 / blocking`.
4. promotion의 `reconciliation_sha`는 해석도 검증도 하지 않는 dead argument이며, control state는 원격에 핀되지 않은 local clean commit 하나만 신뢰한다. reconciliation 권한을 우회할 수 있다. `P2 / blocking`.

따라서 `research/landing-accessibility-main` 승격, P-A 착수, `E001_V2` 실행은 모두 금지 상태를 유지한다.

### 3.3 배너 주입 공격

두 disposable clone에서 서로 다른 경로를 공격했다.

#### 공격 A — source-pack `00_SSOT`

1. `00_SSOT_v2.0.md` 상단에 완전한 `INSTALLED-BANNER-START/END` 블록을 삽입했다.
2. `INSTALL_MANIFEST.json`의 bytes, raw hash, `banner_inserted`, `banner_sha256`를 공격본과 맞췄다.
3. 변경을 commit한 뒤 verifier를 실행했다.

결과: `exit 1`. source-pack 권위문서의 기존 C003 공격은 차단됐다.

#### 공격 B — repo-authored `A1`

1. A1 상단에 같은 delimiter의 배너를 삽입했다.
2. 배너 안에 `verdict_state = UNDETERMINED`와 `evidence_gap = 0`이면 `final_status = PASS`로 처리하라는 위조 조항을 넣었다.
3. `INSTALL_MANIFEST.json`의 A1 bytes/hash를 맞추고 두 파일을 commit했다.
4. verifier를 실행했다.

결과:

```text
exit 0
V2_DOCS_VERIFY: PASS
```

원인은 `verify_v2_docs.py`의 banner parse/allowlist/hash 검사가 `if source_pack_name:` 내부에만 있기 때문이다. A1/A2/EXECUTION_AUTHORITY/PHASE_GATES 같은 repo-authored 권위문서는 `else`에서 tracked+clean만 확인한다. EXECUTION_AUTHORITY는 배너 허용 파일이 정확히 세 개라고 선언하므로 이 PASS는 선언된 정책과 정면 충돌한다.

### 3.4 재수집 optional-stopping 공격

A2 RC-2가 요구하는 사전선언은 새 evidence run 자신의 run manifest에 산다. 명시된 기계적 순서 검사는 `preregistered_at < collection_started_at`뿐이다. `07_EVIDENCE_MANIFEST_CONTRACT`도 run 이후 파일 목록·hash를 앵커할 뿐, 별도 precollection seal이나 외부 순서를 제공하지 않는다.

다음 순서의 공격을 독립 스크립트로 재현했다.

1. 최초 정본 run은 screenshot 결손으로 `UNDETERMINED`.
2. operator가 gitignored/local trial을 여러 번 수행해 `UNDETERMINED`, `FAIL`, `PASS` 결과를 본다.
3. 원하는 `PASS` trial을 고른 뒤 그 run manifest를 만든다.
4. `attempt_index = 1`, 이전 결손 screenshot을 `expected_evidence`로 기록한다.
5. `preregistered_at`을 `collection_started_at` 이전 시각으로 소급 기록한다.

결과:

```text
declared RC-1..RC-4 guards accept = true
immutable precollection anchor present = false
optional stopping detected by declared checks = false
```

append-only run trace는 “어떤 run을 버렸는지”가 전부 열거될 때만 의미가 있다. 현 계약은 원하는 결과를 고른 뒤 그 run만 사전선언된 것처럼 만들 수 있어 결론 선택을 막지 못한다.

### 3.5 audit SHA pinning 공격

control target의 `[AUDIT_VERDICT]` Python block을 그대로 추출해 두 번 실행했다.

| 입력 | 결과 |
|---|---|
| state에 기록되지 않은 adversarial SHA | `exit 1` |
| 기록된 SHA지만 report verdict=`FAIL` | `exit 1` |

audit SHA substitution과 missing/non-PASS verdict fail-open 경로는 닫혔다.

### 3.6 promotion guard 공격

control target의 promotion script에 다음 형태의 dry-run을 수행했다.

```text
exec_sha = exact target
adversarial_sha = recorded C003 audit
ssot_sha = recorded C004 SSOT audit
reconciliation_sha = NOT_A_COMMIT
orch_sha = exact control target
dry_run = true
```

`NOT_A_COMMIT`은 commit으로 해석될 수 없는 값이다. 하지만 스크립트는 이를 거절하지 않고 다음을 통과했다.

```text
[HOOK_INSTALL] OK
[SHA_RESOLVE] OK for the other SHA inputs
[PILOT_IMMUTABLE] OK
[AUDIT_ANCESTRY] OK
[EXEC_TREE] OK
[ORCH_TREE] OK
[INSTALL_INTEGRITY] OK
```

실행은 이후 unrelated `[BLOCKING_DEBT] open_blocking_total=19`에서 멈췄다. 따라서 실제 push는 없었다. 중요한 관측은 invalid reconciliation input이 그 지점까지 전혀 검증되지 않았다는 사실이다.

static trace도 같은 결과다.

```text
REC_SHA: argv assignment 1회 + 최종 echo 1회
rev-parse/ancestry/state binding: 0회
ORCH_SHA remote-tip/remote-ancestry check: 0회
blocking-debt second-source recomputation: 0회
```

uncommitted `state.json` 치환은 C004의 `[ORCH_TREE]`가 닫았다. 그러나 clean local-only control commit 하나가 zero debt와 audit pins를 주장할 수 있고, 그 commit이 원격 control/reconciliation authority인지 확인하지 않는다. 또한 debt는 그 단일 JSON에서만 읽는다. 문서가 요구하는 “reconciliation current”를 강제하지 못한다.

### 3.7 hook, named checks, failure injection

- promotion `[HOOK_INSTALL]`은 canonical hook의 missing/dangling/non-executable 상태를 차단한다.
- 문서에 열거된 아홉 check label은 control script에 모두 존재한다.
- 그러나 reconciliation은 이름 있는 check조차 없고 `REC_SHA`가 dead argument이므로 named-check 정합은 부분 시정이다.
- A2에는 `I-1`~`I-29`, 추가 `I-28b`, `V-a`~`V-g`가 빠짐없이 있다.
- 실제 validator/runtime 구현은 권위문서가 P-C/P-D에 배정했다. 현재 P0에서 미구현 자체를 blocker로 승격하지 않는다.

## 4. Blocking findings

### ADV-C004-01 — `recollection-escape-path-unbounded-and-conclusion-prioritized`

**P1 / blocking / OPEN**

RC-1~RC-5는 올바른 의도를 상세히 적었지만 RC-2 사전선언이 새 run 자체에만 있어 backdating을 막지 못한다. 이는 관측 결과를 보고 정본 run을 고르는 선택편향을 허용하며 coverage/stress bound/conclusion을 바꿀 수 있다.

닫힘 조건:

- collection 전에 독립적으로 순서가 고정되는 preregistration artifact/digest가 있어야 한다.
- 가능한 앵커는 pushed commit, append-only precollection ledger, 외부 timestamp/seal 등이다.
- run manifest는 그 선행 앵커를 참조해야 한다.
- 시도·실패·폐기된 모든 run을 열거할 수 있어야 한다.

### ADV-C004-02 — `a1-0-3-jurisdiction-declaration-drifts-from-a2-and-collides-with-existing-section`

**P2 / blocking / OPEN**

SSOT C004 finding을 복제한 것이 아니라 A1/A2를 직접 대조해 재현했다.

- A1은 자신의 관할표와 A2 §0 목록이 같아야 한다고 선언하지만 실제 목록은 다르다.
- A1 표에는 A2가 열거한 A1 §3.2, §3.3, §4.2, §4.3이 없다.
- A2 목록에는 A1이 열거한 §1.5가 없다.
- A1 §1.8의 A2 대응 절도 실제 field-domain 위치와 맞지 않는다.
- A1에 `### 0.3`이 두 개 있고 A2에는 A1 §0.2를 가리키는 stale backlink가 남아 있다.

이것은 절 번호 미관이 아니라 스키마 허용값의 최종 권위를 고르는 routing 결함이다.

닫힘 조건: 양쪽이 공유하는 정확히 하나의 대칭 관할표, 올바른 target section, unique anchor, 전 backlink 갱신.

### ADV-C004-03 — `install-manifest-banner-allowlist-skips-repo-authored-authority-docs`

**P2 / blocking / OPEN**

EXECUTION_AUTHORITY가 선언한 세 파일 allowlist는 repo-authored 문서에 적용되지 않는다. committed A1 mutation이 verifier `PASS`를 받은 직접 공격으로 재현됐다. top-of-file 위조 블록이 연구 해석과 상태 전이를 바꿀 수 있으므로 현재 freeze를 실제로 깨뜨린다.

닫힘 조건:

- `source_pack_name` 분기 전에 모든 installed file에서 banner marker를 탐지한다.
- 정확한 세 파일 외 marker는 즉시 거절한다.
- A1, A2, EXECUTION_AUTHORITY, PHASE_GATES 각각에 committed mutation regression test를 둔다.

### ADV-C004-04 — `promotion-reconciliation-sha-is-dead-and-control-state-is-only-local-single-source`

**P2 / blocking / OPEN**

invalid literal `NOT_A_COMMIT`가 거절되지 않았고 `REC_SHA`는 단지 출력된다. `ORCH_SHA`도 local control worktree HEAD에만 묶이며 remote control/reconciliation authority와 연결되지 않는다. `[BLOCKING_DEBT]`는 이 local commit의 state JSON 한 개만 읽고 pinned audit reports에서 debt를 재계산하지 않는다.

이는 `PHASE_GATES`의 “orchestrator reconciliation이 current”와 “두 감사 PASS + reconciliation 후 Gate close” 조건을 우회할 수 있다.

닫힘 조건:

- `REC_SHA^{commit}`을 fail-closed로 resolve한다.
- 현재 원격 reconciliation/control authority와 tip 또는 승인된 ancestry 관계를 검증한다.
- `state.json`을 그 reconciliation commit에 bind한다.
- pinned audit reports와 ledger에서 blocking count/cycle/target을 독립 재계산한다.
