## 3. 항목 1 — MIN-4 양자화: **직접 공격 (a)~(d)**

`A1:363-390` 의 시정.

```
( marked_primary desc, area_quantized desc, selector asc )
area_quantized = floor(area_css_px2)      # CSS px² 단위로 절사
```

### 3.1 (a) `floor` 양자화로 `selector` 가 정말 도달되는가 — **조건부로만 그렇다**

C008에서 flip을 냈던 것과 **같은 `0.01px²` 주입**을 나란히 태웠다.

```
nominal 120.00 / 120.00
  run1(무주입)  PREV(raw)    ['…li:nth-of-type(1)>a', '…li:nth-of-type(2)>a']
  run2(+0.01)   PREV(raw)    ['…li:nth-of-type(2)>a', '…li:nth-of-type(1)>a']   ← C008 재현
  run2(+0.01)   TARGET(floor) ['…li:nth-of-type(1)>a', '…li:nth-of-type(2)>a']   ← 유지
```

**양의 방향 주입에서는 사실이다.** 두 값이 같은 정수 버킷에 들어가 `selector` 가 도달된다.

**그러나 부호를 뒤집으면 TARGET 규칙 자신이 flip을 낸다.** §2.5가 새로 넣은 검증 케이스는
*"면적을 `0.01px²`만큼 흔들었을 때"* 라고만 적고 **부호를 지정하지 않는다.** fixture는 저작물이라
nominal 면적이 정수인 경우가 흔하다(예: 100×50 = `5000.00`). 그 위에서 네 케이스를 전부 돌렸다:

| 주입 | areas | floors | 결과 |
|---|---|---|---|
| `a_card` **+0.01** | `5000.01` / `5000.00` | `5000` / `5000` | 유지 |
| `a_card` **−0.01** | `4999.99` / `5000.00` | **`4999` / `5000`** | **FLIP** |
| `b_card` **+0.01** | `5000.00` / `5000.01` | `5000` / `5000` | 유지 |
| `b_card` **−0.01** | `5000.00` / `4999.99` | `5000` / `4999` | 유지 |

**4케이스 중 1건이 flip한다.** §2.6이 "`0.01px²` 차이는 같은 정수 버킷에 들어간다"고 단언한
바로 그 크기에서, §2.5가 신설한 바로 그 검증 케이스가 **반례가 된다.**
시정본은 자기가 새로 쓴 검증을 통과하지 못한다.

### 3.2 (b) 버킷 경계 케이스는 잔여로 인정할 만한 크기인가 — **아니다. 지배적 경우다**

문서의 잔여 인정 문장:

> 버킷 경계(예: `119.99` vs `120.01`)를 가로지르는 흔들림은 여전히 갈릴 수 있으나,
> **그 크기의 차이는 서브픽셀 잡음이 아니라 실제 레이아웃 차이다.**

**이 문장은 거짓이다.** 양자는 **면적(px²)** 단위인데 물리적 흔들림은 **선형(px)** 단위이고,
면적은 선형 잡음을 둘레만큼 증폭한다 — `Δ(w·h) ≈ h·Δw + w·Δh`.

`Δw = 0.01px` — probe의 `toFixed(2)` 격자이자 Chromium LayoutUnit(1/64 px ≈ 0.0156)급,
즉 **표현 가능한 잡음의 하한** — 에서:

| control | `Δw = 0.01px` → `Δarea` | `floor(1px²)` 중화 |
|---|---|---|
| nav 버튼 88×44 | `0.44 px²` | **O** |
| CTA 335×48 | `0.48 px²` | **O** |
| **2열 카드 171×120** | **`1.20 px²`** | **X** |
| **3열 카드 119.67×160** | **`1.60 px²`** | **X** |
| **히어로 카드 335×220** | **`2.20 px²`** | **X** |
| 소형 아이콘 24×24 | `0.24 px²` | O |

**MIN-4가 이름으로 든 두 예시 중 "그리드의 동급 카드" 가 정확히 실패 쪽이다.**
`Δw = 0.05px` 이상에서는 **여섯 geometry 전부** 1px²를 넘는다.

**위상 무작위화 flip 율 실측** (동일 nominal 형제 2개, 각자 독립 선형 jitter, N=40000, run-to-run 경로 flip):

`Δw = ±0.01px`:

| geometry | raw (PREV) | **floor 1px² (TARGET)** | floor 10px² | floor 100px² |
|---|---|---|---|---|
| nav 버튼 88×44 | 41.3% | **16.9%** | 0.0% | 0.0% |
| CTA 335×48 | 41.2% | **16.6%** | 5.7% | 0.0% |
| 2열 카드 171×120 | 41.1% | **41.4%** | 10.9% | 0.0% |
| 3열 카드 119.67×160 | 41.5% | **41.9%** | 8.7% | 0.0% |
| 히어로 카드 335×220 | 41.7% | **42.0%** | 15.9% | 15.8% |

`Δw = ±0.5px` (문서가 명명한 **폰트 로딩·이미지 리플로우·스크롤바 유무** 급):

| geometry | raw (PREV) | **floor 1px² (TARGET)** | floor 100px² |
|---|---|---|---|
| nav 버튼 88×44 | 50.1% | **49.7%** | 0.0% |
| CTA 335×48 | 50.5% | **50.1%** | 16.5% |
| 2열 카드 171×120 | 49.9% | **50.2%** | 34.5% |
| 히어로 카드 335×220 | 50.3% | **49.9%** | 41.2% |

두 가지를 말한다.

1. **카드급 control에서 `floor(1px²)` 의 개선은 0이다** (41% → 41~42%). 최선의 경우(nav·CTA)에도
   41% → 17%로 줄 뿐 없어지지 않는다.
2. **문서가 스스로 명명한 세 jitter 원인(폰트 로딩·이미지 리플로우·스크롤바)은 전부 선형 0.5px
   이상급이며, 그 구간에서 `floor(1px²)` 의 개선은 전 geometry에서 0이다.**
   시정은 자기가 지목한 원인 중 **하나도** 중화하지 못한다.

**따라서 잔여로 인정할 크기가 아니다.** 인정된 잔여는 예외적 경계 케이스여야 하는데,
실제로는 대상 control이 클수록 확실히 발생하는 **지배적 경우**다.

**다른 양자화가 필요한가 — 그렇다. 다만 "더 큰 floor" 하나로는 부족하다.**
어떤 결정적 양자화도 경계를 가지므로, nominal이 경계에서 jitter 거리 안에 있으면 여전히 갈린다.
flip 율은 대략 `min(1, δ/Q)/2` 로 움직인다(`δ` = 면적 jitter, `Q` = 양자). 그러므로 요구는
**`Q ≫ δ`** 이며, `δ` 가 control 크기에 비례하므로 **절대 양자 하나로는 스케일 정합이 성립하지 않는다.**
표에서 `floor(100px²)`가 소형에서는 완전 중화되나 히어로 카드에서 15.8%를 남기는 것이 그 증거다.

### 3.3 (c) `floor` 가 면적 0 근처나 음수에서 이상 동작하는가 — **이상 동작 없음. 다만 NULL 규칙 부재**

- **음수: 발생하지 않는다.** `area_css_px2 = +(b.w*b.h).toFixed(2)` 이고 `getBoundingClientRect` 의
  `width`/`height` 는 음수가 될 수 없다. 음수 **좌표**(`x`/`y`)는 곱에 들어가지 않는다.
  따라서 `floor` 와 절단(truncate)이 갈리는 구간에 도달할 수 없다. **여기는 깨끗하다.**
- **면적 0 근처: 무해하다.** 버킷 0 = `[0, 1)` 이라 면적 `0.0` 과 `0.99px²` 가 함께 들어가지만,
  그 안에서는 `selector` 가 결정하므로 오히려 결정적이다. 그 크기의 요소는 어차피 타깃 크기
  하한 아래다.
- **그러나 `NULL` 규칙이 없다.** probe는 bbox 부재 시 `area_css_px2: null` 을 낸다
  (`l0_probe.js:294` `b ? +(b.w*b.h).toFixed(2) : null`). 명세 문면 `area_quantized = floor(area_css_px2)`
  에는 `NULL` 처리가 없고, `floor(NULL)` 은 `TypeError` 다. 현행 엔진은
  `c.get("area_css_px2") or 0.0` 로 흡수하지만 **그것은 코드의 우연이지 명세가 정한 것이 아니다.**
  한 줄이면 닫힌다.

### 3.4 (d) 이 변경이 `MIN-2` 나 다른 MIN 규칙을 깨는가 — **MIN-2는 무사. MIN-5·MIN-8·§7에 미등재 결손**

| 규칙 | 판정 |
|---|---|
| **MIN-2** (폭우선·짧은 경로 우선) | **깨지지 않는다.** 정렬 키는 *한 state 안의 후보 순서*이고 열거 레벨 순서는 `deque`+`popleft` FIFO가 정한다. 두 축이 직교한다 |
| **MIN-4 전순서 자체** | **유지된다.** `floor` 는 면적의 함수이고 `selector` 는 dedup 후 유일하므로 삼중키는 여전히 전순서다 |
| **MIN-6** (`k`·`m` 같은 경로) | 무영향 |
| **MIN-5** (최소성의 **범위**) | **영향받는다. 그리고 문서가 그것을 적지 않는다** |
| **MIN-8** (동결 산출물) | **영향받는다. 그리고 문서가 그것을 적지 않는다** |

**MIN-5** — `_activation_candidates` 는 정렬 → dedup → `BRANCHING_LIMIT` 절단이다.
양자화는 순서만이 아니라 **절단 경계를 바꾼다.** 실증:

```
후보: b_c 500.00 · c_d 400.00 · d_e 300.00 · z_big 120.90 · a_small 120.10
  raw   상위4: ['b_c', 'c_d', 'd_e', 'z_big']
  floor 상위4: ['b_c', 'c_d', 'd_e', 'a_small']     ← 실제로 더 큰 z_big 이 탈락
```

같은 버킷 안에서 컷이 면적이 아니라 **selector 문자열**로 결정된다. MIN-5는 `BRANCHING_LIMIT`을
두고 "**이 값이 최소성의 범위를 정한다**"고 적었는데, 이제 그 범위를 `BRANCHING_LIMIT` 과 양자가
**공동으로** 정한다. 결정성 관점에서는 개선이다(경계 후보가 잡음이 아니라 문자열로 갈린다).
문제는 **§7 P-C 검증·동결 표에 양자가 등재돼 있지 않다는 것**이다 — `BRANCHING_LIMIT | 4` 행은
있으나 `area_quantized` 단위 행이 없다. §2.6 본문은 "P-D에서 검증·동결한다"고 적는데
**등재부가 그 약속을 받지 않는다.** 내가 V2-C008 처방에 "§7에 엔진 측 이행 의무를 한 줄 등재한다"를
넣은 자리가 정확히 이곳이며, 이행되지 않았다.

**MIN-8** — 동결 산출물은 "경로 step 열 · `path_sha256` · **산출 당시의 예산값** · NED/IED/MPFED"를
담는다. 양자는 예산값이 아니므로 담기지 않는다. 양자를 바꾸면 같은 대상에서 다른 경로가 최소가
되는데, 동결본만 보고는 **무엇에 대한 최소인지 복원할 수 없다** — MIN-8이 예산값을 함께 동결한
바로 그 이유가 양자에도 그대로 적용된다.

### 3.5 판정 — `min-4-selector-tiebreak-does-not-neutralize-subpixel-jitter` **OPEN 유지 (P2)**
