**질문 8에 대한 정직한 판정: 다른 브랜치의 문서를 이 브랜치의 선언으로 무력화할 수 없다.**

`docs/v2/EXECUTION_AUTHORITY.md` §3은 v1 실행지침을 supersede한다고 선언한다.

> L54 `| `docs/PHASE_EXECUTION_DIRECTIVE_v5.0.md` | `control/landing-orchestrator` 브랜치 | `SUPERSEDED_FOR_SCOPE` / `OPERATIONAL_GUARDS_INHERITED` |`

그러나 `origin/control/landing-orchestrator:research/landing_accessibility/docs/NEXT_SESSION_ENTRYPOINT.md`는
그 선언을 전혀 반영하지 않는다. 원문 첫 3줄:

> ```
> # NEXT SESSION ENTRYPOINT
>
> 이 파일을 먼저 읽고 순서대로 진행한다.

`6. **P-A ANALYSIS FOUNDATION 부터 시작한다.**`, `7. **READY_FOR_E001 에서 반드시 정지한다.**`,
`운영 헌장: **docs/PHASE_EXECUTION_DIRECTIVE_v5.0.md**`. **`v2` 문자열이 이 파일에 한 번도 등장하지 않는다.**

```
$ git ls-tree -r --name-only origin/control/landing-orchestrator | grep -i CLAUDE.md

```

root `CLAUDE.md`는 (설계상 옳게) 수정되지 않았으므로 v2 포인터가 없다.

`docs/v2/`는 그 체크아웃에 **파일로 존재하지 않는다.** 세션은 v1 SSOT를 권위로 읽고 `LANDING_ONLY` 범위로

선언이 브랜치 C의 파일에 주석을 달 수 없다. 이 커밋의 supersede는 **읽는 사람이 이미 v2 브랜치에 있을 때만** 작동한다.

**P0가 아닌 이유**(과탐 방지 차원에서 명시): v1 자산 보존은 설계상 의도된 것이고, 결손은 "역방향 포인터 부재"
