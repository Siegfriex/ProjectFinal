## §1 Plane 구조 — 생산자와 판정자를 분리한다

```
A   Authority / Research Governor    연구계약 · phase gate · 결정 · reconcile · claim acceptance
B   Production / Measurement          구현 · 수집 · 분석. 자기 산출을 self-approve 하지 않는다
C   Independent Assurance             exact-SHA 독립 감사 · 재계산 · 적대적 검증. production 미수정
D   Research Lab (NON_CANONICAL)      탐색. 직접 지시 금지. C replication 경유로만 승격
```

### 이 구조가 실제로 작동한 근거

```
A 의 오류 3건을 C·B·labeler 가 잡았다
B 의 오류 10건을 B 가 스스로 8건, C 가 2건 잡았다
C 의 오류 2건을 C 가 스스로 잡았다
D 의 오류 1건을 D 가 스스로 철회했다
```

**A 의 자기 검산만으로는 A 의 오류가 잡히지 않았다.** 이것이 분리를 유지할 실증적 이유다.

### 승격 경로 (D)

```
NON_CANONICAL  →  C replication  →  C CONFIRMED 이고 result-affecting  →  A decision queue
```

**A 가 D 를 직접 읽지 않는다.** 병목 방지가 아니라 오염 방지다 —
검증되지 않은 탐색 결과가 A 판단의 근거가 되면 판정의 계보가 끊긴다.

## §3 검증 규율 — 이 세션에서 실증된 것

### 규율 1 · 0건 보고는 대조군 없이 증거가 아니다

```
필요조건   스캔 대상이 실제로 존재했는가
충분조건   대조군이 non-zero 인가 — "0 이 아닌 것도 잡힌다" 는 증명
음성 대조   심은 조건이 다시 검출되는가
```

**이 세션에서 다섯 번 위반됐고 다섯 번 다른 사람이 잡았다.**

```
A   gate_signals 를 최상위에서 조회        실제 경로는 raw_features 아래
A   degenerate 를 파일 크기로 스캔          132KB·676KB 를 놓쳤다
A   존재하지 않는 경로에 grep               0 을 부재로 읽고 여섯 번 보고했다
C   grep 범위를 하위 디렉터리로 제한        repo-root 를 놓쳤다
W1  회귀 스윕 범위 제한                     한 파일군을 놓쳤다
B   서비스 키 리스트를 다른 형식과 대조      교집합 0 을 부분집합 부정으로 읽을 뻔했다
```

**공통 형태: 조회 방식이 답을 만들었다. 데이터를 잘못 읽은 것이 아니다.**

### 규율 2 · 비율은 n 과 구간 없이 근거가 아니다

```
점추정만 제시하지 않는다
n 과 구간(Wilson 등)을 함께 낸다
기준과 비교할 때 구간이 기준을 포함하는가 · 겹치는가 · 떨어져 있는가를 명시한다
```

**실증**: `0.750` 을 인간 상한으로 단정했으나 95% CI `[0.505, 0.898]` 이 기준 `0.85` 를 포함했다.
같은 n 이 반대 방향 주장에도 똑같이 약했다.

### 규율 3 · 귀속은 분리 측정 없이 하지 않는다

```
두 변경이 같은 커밋 구간에 들어갔으면 개선을 어느 쪽에 귀속시킬지 주장하지 않는다
분리할 수 없으면 "분리되지 않았다" 고 적는다
```

**실증**: abstain 29→25 가 fallback 성과처럼 보였으나 실제 원인은 rule 결함 시정이었다.
*"NLP fallback 도입으로 29→25 개선"* 은 **모든 단어가 참이면서 전체가 거짓**인 문장이다.

### 규율 4 · composition 은 배정이 아니라 diff 로 기재한다

```
assigned     티켓이 갔다        T6
implemented  보고했다           T6
merged       바이트가 있다      T1 — diff 로 확인하고 확인 명령을 함께 적는다
```

### 규율 5 · 제거 확인은 추가 확인과 다른 검사다

```
정정 문서를 새로 쓰는 것    ≠    옛 문구가 사라졌는지 보는 것
```

**이 세션에서 세 번, 정정 후 grep 이 무주석 잔존을 잡았다.**
발행된 티켓은 append-only 이므로 수정하지 않고 그 안의 오류는 기록으로 남긴다.

## §4 게이트 운영

```
게이트는 관측 이전에 정한다
관측이 나쁘다는 이유로 재정의하지 않는다
결과가 좋다는 이유로도 바꾸지 않는다 — 같은 실패다
```

### A 의 GO 조건 (프로토콜 §14)

```
세 정보가 같은 exact SHA 를 가리킬 때만 GO
   1  B completion (self_approved=false)
   2  C assurance PASS 또는 ACCEPTABLE_WITH_NONBLOCKING
   3  authority map / SSOT 정합
```

### PASS 문서의 필수 절

```
"이 게이트가 검증하지 않은 것" 을 반드시 포함한다. 비면 발행하지 않는다
통과값 하나만 남기면 그 값이 무엇을 삼켰는지 사라진다
```

### 조건부 HOLD 의 사전 선언

```
HOLD 조건과 그때의 선택지를 결과 보기 전에 적는다
그때 가서 만들면 결과를 본 뒤 만든 선택지가 된다
같은 질문("HOLD 를 피하려고 이유를 찾는 것인가")을 두 번 하면 답이 달라져야 한다
```

## §5 반복 실패 형태 — `presence ≠ operative`

**이 세션 최대 발견.** 계약이 `상태`로 정의한 것을 구현이 `존재`로 대체한다.

```
코드 축   login control 존재      →  target kill
          어휘 존재               →  gate 관측됨
          iframe 존재             →  terminal
          title 존재              →  PASS
          hittable                →  enabled
          기하학적 겹침            →  방해
          scope 정의 존재          →  scope 가 실행을 구속함
          deadline 필드 존재       →  마감이 강제됨
통계 축   계산하기 쉬운 점추정      →  알아야 하는 불확실성
보고 축   배정된 티켓              →  병합된 바이트
```

```
규칙   계약이 상태로 정의한 predicate 는 상태를 소비해 판정한다
검증   반드시 양방향 대조군 —
       존재하지만 작동 않는 것은 성립하지 않아야 하고
       작동하지만 전형적 신호가 없는 것은 성립해야 한다
       한 방향만 보면 "아무것도 성립시키지 않는" 구현도 통과한다
```

### 거울상 — 측정 실패의 처리 방향

```
측정 실패 → FAIL 로 전이   금지
측정 실패 → PASS 로 전이   금지 (못 잰 것을 분모에서 빼고 PASS 하지 않는다)
```

**PASS 와 FAIL 은 제외에 대해 비대칭이다** — FAIL 은 존재 주장이고 PASS 는 전칭 주장이며,
전칭 주장만 표본 누락에 취약하다.

## §6 안전 · 실행 통제

```
exactly-once      idempotency key 검사는 launch 이전. 사후 원장 차단은 exactly-once 가 아니다
                  억제는 오프라인에서 증명 가능해야 한다 —
                  real launch 로 검증할 수 없다. real launch 가 막으려는 대상이기 때문이다
방어 겹           scope 강제가 실행기의 정확성에 의존하지 않게 한다
                  실행기가 유일한 방어면 firewall 은 그 순간 아무것도 하지 않는다
fail-closed       릴리스 문서 부재·status 불일치·해시 불일치는 전부 거부
승인의 바인딩      릴리스 문서가 표본 해시를 실어야 한다 — 표본이 조용히 바뀌는 것을 막는다
자기선언 발신자    본문 헤더는 발신자 주장이지 인증이 아니다
                  worker 는 자기 plane 을 거치지 않은 지시를 실행하지 않는다
소유 경계         한 파일을 두 worker 가 만지지 않는다
                  소유 밖 파일이 필요하면 이름으로 열거해 편입한다 — 일반 허가로 열지 않는다
검산은 읽기        자기 소유 아닌 워크트리의 git 상태를 바꾸지 않는다
                  완료 후에도 적용한다 — 완료는 재개 불가를 뜻하지 않는다
```

```

   분모 정의 · 상한 · 결측 원인 · 지배 변수 · 경합 사례 · LOW_N · 감도분석 목록

```

**무인 진행 중에는 기준을 바꾸는 것을 지적할 사람이 없다.**
사전등록된 항목이 그 구간의 유일한 방어선이다.

## §8 재현 가능성

```
동결된 표본은 재현 가능해야 한다 — 재현 불가능한 표본은 동결된 것이 아니다
집계 산출물은 root set 과 필터 조건과 조인 키를 명시한다
   두 경로가 다른 값에 도달했다고 둘 중 하나가 틀린 것이 아니다. 경계가 다를 수 있다
   두 경로가 같은 값에 도달했다고 같은 것을 센 것도 아니다
Git 밖 산출물은 해시를 Git 에 남긴다 — "로컬에 있다" 는 인계가 아니다
결과를 덮어쓰지 않는다. 새 실험은 새 run. 틀린 값이 남아 있는 것이 정상이다 — 그것이 정정 이력이다
```
