# 인증 join 규칙 — `01 §8` 3요건의 조작화

```
status = SHADOW_PREPARATORY · shadow_lane = LANE_B
base_sha = d5f1da5652953542d5c8be377026cc3293f2075a
authoritative = false · real_target_outcome_used = false
구현 = shadow/lane_b/scripts/certification_join.py
```

> **이 문서는 infrastructure 명세다.** `PHASE_GATES §4.1` 7항 · `§4.6` 에 따라
> 인증 결과로 target 을 고르거나 representative task 를 고르지 않는다.
> `certification_join.assert_not_used_for_selection()` 이 join 전후 target 집합의
> 동일성을 실행 시점에 검사한다.

---

## 1. 문제 — 3요건만으로 1:1 이 성립하지 않는다

`01 §8` 은 `certified_current = 1` 을 **유효기간 + 대상범위 + 서비스 동일성**의 곱으로 정의하지만
각 요건을 무엇으로 판정하는지 말하지 않는다. 레지스트리 실측이 그 공백의 크기를 보여준다.

| 층 | 행 | 이름 | URL | 등록도메인 | 최대 이름중복 | 최대 URL중복 |
|---|---|---|---|---|---|---|
| 전량 | 2283 | 1193 | 1167 | 557 | **25** | **11** |

한 이름이 25행, 한 URL 이 11행에 걸린다. 이 상태에서 이름이나 URL 로 join 하면
web target 하나에 인증 여러 건이 붙는다.

## 2. 요건1 — 유효기간. fan-out 의 **대부분은 갱신 이력이다**

```
cert_valid_candidate = 1  ⟺  cert_start ≤ audit_date ≤ cert_end
```

`certification_status_listed` 를 **보지 않는다.** 게시 상태는 레지스트리의 주장이고
날짜는 증거다. 둘이 어긋나면 계산된 기간이 이긴다 (fail-closed).

| 층 | 행 | 이름 | 등록도메인 | 최대 이름중복 | 최대 등록도메인중복 |
|---|---|---|---|---|---|
| 요건1 통과 | **226** | 212 | 154 | 5 | 18 |

전량 2283 → 226. **이름 중복 25 → 5.** 큰 fan-out 의 정체가 연차 갱신이었음이 확인된다.

### 2.1 경계 결함 처리 규칙 (EDA-00 지적 2건 + 1건)

| `period_status` | 실측 | 규칙 | 근거 |
|---|---|---|---|
| `NOT_YET_EFFECTIVE` | **1건** — 인증 2521 `국립망향의동산`, start `2026-08-27` > audit_date `2026-08-26` | 유효후보 **제외** | 게시가 `VALID` 이나 아직 효력이 시작되지 않았다. 미래 시점의 유효성을 현재 유효로 세면 `certified_current` 의 의미가 무너진다 |
| `PERIOD_INVERTED` | **1건** — 인증 1095 `주택관리공단 대표 홈페이지`, `2020-12-12 ~ 2020-12-11` | 유효후보 **제외** | `end < start` 는 기간을 신뢰할 수 없다는 뜻이다. 어느 쪽이 오타인지 우리가 정할 수 없으므로 유효하다고 보지 않는다 |
| `PERIOD_MISSING` | **1건** — 인증 1812, `service_name` 이 `-` 이고 기간 결측 | 유효후보 **제외** | 요건1 을 시험할 입력이 없다. 결측을 통과로 해석하지 않는다 |

**정합성 실측**: 게시 `VALID` 인데 요건1 불통과 **1건**(위 2521), 게시 비-`VALID` 인데
요건1 통과 **0건**. 따라서 `VALID` 게시 227 → 유효후보 **226**. 스냅샷 매니페스트의
`in_period_at_audit = 226` 과 일치한다.

세 규칙은 전부 fail-closed 이며, 셋 다 **행을 지우지 않는다.** `period_status` 컬럼에
사유를 남기고 요건1 에서 떨어뜨릴 뿐이다.

## 3. 요건2 — 대상범위. **남은 fan-out 은 갱신이 아니라 범위 분리다**

요건1 을 통과하고도 같은 URL·같은 기간에 인증이 둘 존재한다. 실측:

```
2333  맥도날드(모바일웹)  https://www.mcdonalds.co.kr  2025-12-17~2026-12-16  VALID
2332  맥도날드           https://www.mcdonalds.co.kr  2025-12-17~2026-12-16  VALID
```

구분자는 `service_name` 의 **후행 괄호**뿐이다. 즉 이 레지스트리에서 대상범위는
별도 컬럼이 아니라 이름 접미사로 표현된다. 접미사 어휘를 실측으로 닫는다.

| `scope_effective` | 뜻 | 유효 226행 중 | 요건2 |
|---|---|---|---|
| `SCOPE_MOBILE_WEB` | `(모바일웹)` | **7** | 통과 |
| `SCOPE_UNDIFFERENTIATED` | 접미사 없음, 모바일웹 형제행도 없음 | **200** | 통과 |
| `SCOPE_DESKTOP_IMPLIED` | 접미사 없으나 **같은 등록도메인·같은 유효기간에 `(모바일웹)` 형제행이 있다** | **6** | 불통과 |
| `SCOPE_LANGUAGE_VARIANT` | `(영문)` `(국문)` `(일어)` `(중국어-간체)` … | **7** | 불통과 |
| `SCOPE_SUBSYSTEM` | `(개발자포털)` `(TREE)` `(클린아이)` … | **6** | 불통과 |

요건2 통과 **207 / 226**.

### 3.1 `SCOPE_DESKTOP_IMPLIED` 가 왜 필요한가

접미사 없는 행을 무조건 통과시키면 맥도날드 쌍에서 **둘 다** 살아남아 1:1 이 깨진다.
맥도날드 패턴은 기관이 둘을 나눠 신청할 때 **접미사 없는 행이 데스크톱을 뜻함**을 보여준다.
그래서 접미사 없는 행은 형제 `(모바일웹)` 행이 없을 때만 모바일웹을 포괄한다고 읽는다.

이 규칙이 실제로 발화한 행이 **6건**이며, 이는 `SCOPE_MOBILE_WEB` 7건과 거의 짝을 이룬다
(1건은 모바일웹 인증만 있고 평문 형제가 없다). 규칙이 맥도날드 1건에 맞춘 특례가 아니라
레지스트리 전반의 신청 관행과 맞는다는 실측 근거다.

## 4. 요건3 — 서비스 동일성. 등록도메인은 **필요조건이지 충분조건이 아니다**

### 4.1 등록도메인은 PSL 파서로만 판정한다

문자열 마지막 두 라벨 비교는 한국 도메인에서 무너진다 —
`www.gmarket.co.kr` 과 `www.auction.co.kr` 이 둘 다 `co.kr` 이 된다.
`src/landing_accessibility/registered_domain.py` (C013 살베지) 가 PSL 목록으로 경계를 찾고,
목록 파일의 sha256 을 `psl_provenance()` 로 고정한다. IP 리터럴은 등록도메인이 정의되지
않으므로 `None` 이다 (실측 1건: `http://210.118.135.41` → 순진하게 넣으면 `135.41` 이 나온다).

### 4.2 도메인 단독 판정을 금지한 이유 — 실측 거짓양성 3건

요건1·2 통과 후 등록도메인별 생존자 수를 세면:

```
등록도메인 151종 중 생존자가 정확히 1건인 것 127종 = 84.1%
                    생존자가 2건 이상인 것  24종 (최대 11)
```

84.1% 는 도메인만으로 1:1 이 서는 것처럼 보인다. **그러나 그 84.1% 안에 거짓양성이 있다.**

초안은 "그 도메인의 유효·모바일범위 인증이 정확히 하나면 도메인만으로 동일성이 성립한다"
(`REGISTERED_DOMAIN_SOLE_OCCUPANT`) 는 규칙을 뒀다. 실행 결과 이렇게 나왔다.

```
samsung_internet_browser  ← 인증 2266 '삼성전자승마단'   CERTIFIED_CURRENT
samsung_notes             ← 인증 2266 '삼성전자승마단'   CERTIFIED_CURRENT
samsung_wallet            ← 인증 2266 '삼성전자승마단'   CERTIFIED_CURRENT
```

`samsung.com` 의 유일한 유효인증이 **삼성전자 승마단 사이트**인데, 그것이 삼성 브라우저·
삼성 노트·삼성 월렛 세 건에 한꺼번에 붙었다. 같은 위험이 `spectrummap.kr` 에도 있다 —
한 등록도메인에 서로 다른 시스템 4종이 인증돼 있다.

**따라서 요건3 은 이름 대응을 요구한다.** 도메인만으로는 고르지 않는다.
이름이 어느 것과도 대응하지 않으면 `UNDETERMINED` 이며, **인증이 없다고도 말하지 않는다** —
그 도메인에 유효 인증이 실재하기 때문이다.

이름 비교는 접미사(요건2 토큰)를 떼고 공백·구분자를 지운 뒤 부분문자열 양방향으로 한다.

## 5. 결과 어휘 — 3값, 상호배타, fail-closed

| 값 | `certified_current` | 조건 |
|---|---|---|
| `CERTIFIED_CURRENT` | `1` | 요건1∧2∧3 을 통과한 인증행이 **정확히 하나** |
| `NOT_CERTIFIED` | `0` | 그 등록도메인이 스냅샷 **전량 2283행에 없다**, 또는 있으나 전부 요건1 불통과 |
| `UNDETERMINED` | `NULL` | 그 밖의 전부 |

### 5.1 `NOT_CERTIFIED` 는 미매칭이 아니라 **부재의 실측**이다

`0` 을 쓰려면 부재의 증거가 있어야 한다. 스냅샷 매니페스트가
`snapshot_status = COMPLETE` · `pages_fetched 230` · `declared_last_page 229` ·
`stop_reason = NO_CARDS_AT_DECLARED_END` 로 전수 수집을 보증하므로,
"전량에 그 등록도메인이 없다" 는 진술이 성립한다. 이 근거가 없으면 `UNDETERMINED` 다.

### 5.2 `UNDETERMINED` 를 0 으로 세탁하지 않는다

`A2 §1.11.2` 의 취지대로 `UNDETERMINED` 에서 나가는 길은 증거뿐이다.
현재 발화하는 사유는 두 가지다.

| 사유 | 실측 | 뜻 |
|---|---|---|
| `WEB_TARGET_URL_UNRESOLVED` | **10** | web target URL 이 확정되지 않아 요건2 를 **시험할 입력이 없다.** 인증 부재를 주장할 근거도 없다 |
| `REQ3_IDENTITY_NO_NAME_MATCH` | **3** | 도메인에 요건1·2 통과 인증이 있으나 이름이 대응하지 않는다 (위 samsung.com 3건) |

정의된 채 아직 발화하지 않은 사유: `REQ2_SCOPE_NO_MOBILE_WEB`, `MULTI_SURVIVOR_NOT_1_TO_1`.

## 6. 이 코호트에서의 실행 결과 — **1:1 성립률이 아니라 인증 부재가 결과다**

68 web target group 에 대해:

| `join_outcome` | 건 |
|---|---|
| `NOT_CERTIFIED` | **55** |
| `UNDETERMINED` | **13** |
| `CERTIFIED_CURRENT` | **0** |

### 6.1 전수 대조 — 겹치는 등록도메인이 사실상 없다

358건 관측의 **모든 후보 URL** 최종 등록도메인을 유효인증 154 등록도메인과 교차하면
겹치는 것은 **`samsung.com` 하나뿐**이고, 그 유일한 유효인증은 위에서 본 승마단이다.

레지스트리의 유효 226건은 `.go.kr` / `.or.kr` / `.ac.kr` 공공·교육 부문이 압도적이며,
상용 도메인은 46건에 불과하다. 그중 이 코호트와 이름이 겹치는 것은 **`대한항공` 1건**이다
(인증 2260 · `https://www.koreanair.com` · `2025-09-12~2026-09-11`).

`korean_air` 는 현재 `UNDETERMINED` 인데 그 이유는 인증이 없어서가 아니라
**`www.koreanair.com` 이 우리 HTTP 클라이언트에 응답하지 않기 때문**이다
(read timeout 20s·75s 모두 실패). URL 이 확정되면 이 건은 규칙상 `CERTIFIED_CURRENT` 가 된다
(요건3 `REGISTERED_DOMAIN_AND_NAME`, 레지스트리 `대한항공` ↔ 타겟 `korean_air`).
**이것은 what-if 검증이며 판정으로 기록하지 않았다.**

### 6.2 연구설계에 대한 함의 (판정 아님, 보고 사항)

이 코호트에서 `certified_current` 는 사실상 **상수(0)** 다. 최대치를 잡아도 71건 중 1건이다.
따라서 인증 여부를 층화변수·설명변수로 쓰는 설계는 이 표본에서 검정력을 갖지 못한다.
`PHASE_GATES §4.1` 7항이 금지하는 것은 인증 결과로 **task 를 고르는 것**이므로 이 보고는
그 금지에 걸리지 않지만, 설계 변경 여부는 P-B 이후 Research Director 판단 사항이다.
