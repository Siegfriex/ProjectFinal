## Functions (c_flow_derive)
- `classify_token(token, *, submit_is_activation=True, input_mode=None)` → `{state_changing_activation, task_intent, reveal, dismiss, auth, endpoint, conditional, input_mode, activation_decision}`; raises on non-canonical token (04 §2). Activation membership = STEP1-006 (see table below).
- `derive(task_flow, experienced_flow, *, submit_is_activation, drop_noncanonical=False, input_modes=None, endpoint_surface_rendered_before_gate=None)` → `activation_depth` (+ `_excl_submit` sensitivity, `_conditional_all_in` / `_conditional_all_out` bounds), `depth_conditional_tokens` (STEP1-006 record: index/token/fixture_input_mode/decision/basis), `flow_step_count`, `menu_dependency` (+ `_incl_tab`), `menu_dependency_alt_before_anchor`, `nav_container_depth` (+ `nav_anchor_found`, `nav_anchor_action_token` — P-11), `forced_dismissal_count`, `auth_gate_stage` (+ `_alt_terminal_is_endpoint`, `_alt_reveal_is_discovery`; R13: `UNDETERMINED` for ABSTAIN / incomplete paths, never `NONE`), `endpoint_status`, `flow_evaluable`, `sequence_consistent`, `violations` (contract violations incl. an unresolved conditional token). `input_modes` = a str (row-level `fixture_input_mode`), `{task_index: mode}` or a list aligned with task_flow. Never raises on contract violations — it flags them. Output is Q8 self-checked.
- `auth_gate_stage_from_sequence(seq, *, terminal_auth_is_endpoint=False, endpoint_reached=None, reveal_is_discovery=False, endpoint_surface_rendered_before_gate=None)` (STEP1-011 P-13/P-14 rule), `endpoint_status_from_sequence(seq)`, `resolve_input_mode(mode)`.
- `normalize_synonym_map(map)` (P-30: `canonical → [forms]` → flat bidirectional lookup); `label_relation(visible, accessible, synonym_map, *, casefold=False)` → MATCH / SEMANTIC_EQUIV / DIFFERENT / VISIBLE_ONLY / AX_ONLY / NONE. NFC + whitespace collapse; synonym map is an explicit `{form: canonical_key}` dict (never embeddings, 04 §5).
- `seq_distance(a, b)` → token-level `levenshtein`; **three normalisations always stored (R12)**: `levenshtein_norm` (= lev / max len, **PRIMARY**, the only single-scalar source), `levenshtein_norm_sum` (= lev / sum len), `yujian_bo` (= 2·lev / (sum len + lev), true metric); `lcs_len`, `lcs_sim` (= LCS / max len), `lcs_sim_dice` (alt).
- `pairwise_matrix(rows, *, for_clustering_or_mds=False)` → n×n matrices for all three normalisations + LCS; `primary_distance`, `single_scalar_source`, `distance_rule`; `for_clustering_or_mds=True` sets `clustering_companion="yujian_bo"` (R12: Yujian-Bo must be reported alongside any clustering/MDS). R3: PRIMARY rows only, `filter_condition` literal, `secondary_repeated_ids`. `n_service`, `n_pairs`, guard string. `unique_signatures(rows)` → `signature_counts`.
- `family_summary(rows, numeric_vars, categorical_vars, *, family_id, denominator_map=None)` → R3 filter (`filter_condition="task_role == 'PRIMARY'"`, `n_primary`, `n_secondary_repeated`, `secondary_repeated` block summarised separately); **R2 two denominators** (`denominators.entry_structure_n`, `denominators.endpoint_dependent_n`), `endpoint_reach_rate` (numerator / denominator name / `auth_gate_counts_as_reached`); every numeric/categorical block carries `denominator` + `denominator_n`; endpoint-dependent numerics add `by_endpoint_reached` (R6 Q1 truncation visibility). Numeric: n, n_missing, median, q1/q3 (type-7), iqr, min/max/range; categorical: distribution, k_observed, `entropy_bits`, `entropy_norm`. Always `n_service`, `n_pairs`, `pseudo_replication_guard`. No composite score (05 §3). A variable outside `ENTRY_STRUCTURE_VARS` / `ENDPOINT_DEPENDENT_VARS` must be assigned via `denominator_map` or the call raises.
- `row_evidence_bearing(row)`, `row_flow_evaluable(row)`, `row_endpoint_reached(row, family_id)`, `auth_gate_is_endpoint(family_id)`, `split_by_task_role(rows)`.
- `denominator_chain(candidate, eligible, attempted, evidence_bearing, flow_evaluable, *, family_id, reasons, replaced=(), rows=None)` → **R4 format** `candidate → replaced k → eligible_frozen → attempted → evidence_bearing → flow_evaluable`; `replaced` stage always carries `k` (0 explicit) + `items` (each `target_id / reason / reserve_rank / decided_at / decided_by`) + `by_reason`; reason outside `{APP_REQUIRED_EXCLUDE, NO_PUBLIC_MOBILE_WEB, DEAD_OR_INVALID_URL, PRECHECK_EVIDENCE_DEFECT}` raises; `filter_condition` literal; with `rows` the PRIMARY-only evidence/flow counts are cross-checked; **raises** on non-monotonic / negative counts (05 §6) and on Q8-bare reason strings.
- `entry_zone(x_norm, y_norm, is_floating, is_drawer)` → TOP_LEFT / TOP_CENTER / TOP_RIGHT / MID / BOTTOM / FLOATING / DRAWER per **R7** (below); `entry_zone_record(...)` → zone + `entry_zone_geometry_only` + the raw x/y (always retained).
- `validate_terminal(endpoint_status, terminal_reason, note=None)` → `{ok, violations, ...}` per **R11** table below; `assert_terminal(...)` raising variant.
- `q8_bare_mentions(obj)` / `assert_field_qualified(obj)` → **R6 Q8** guard: every `AUTH_GATE` / `ABSTAIN` must sit under a qualifying key (`endpoint_status`, `action_token`, `task_flow_sequence`, `experienced_flow_sequence`, `signature`, `signature_counts`, or any key ending in `_action_token` / `_endpoint_status` such as `nav_anchor_action_token`) or be written `endpoint_status=…` / `action_token=…` in free text; bare values in mixed lists, bare dict keys and unqualified free-text mentions are listed. `derive`, `family_summary`, `pairwise_matrix`, `denominator_chain`, `validate_terminal` self-check their output; the demo checks the whole artifact.
- `compare_with_mart_row(row, synonym_map=...)` → recompute from raw fields of one `fact_flow_observation` row (uses the row's `fixture_input_mode` / `depth_input_modes` for STEP1-006, validates `endpoint_status × terminal_reason` for R11, carries `task_role`) and diff against B's stored derived values (GATE 3 helper).

## GATE 1 / GATE 3 procedure (recompute-and-compare)
1. Load B's promoted `fact_flow_observation` rows (02 §4); per row call `compare_with_mart_row(row, synonym_map=FROZEN_MAP)` — it reads only `task_flow_sequence`, `experienced_flow_sequence`, `visible_label_text`, `accessible_name`, `entry_x_norm/entry_y_norm`, `nav_container_type`, `fixture_input_mode`/`depth_input_modes`, `task_role`, `terminal_reason`; B's derived columns are used only in the `diffs` output. Where a `fact_flow_step` table exists, rebuild the two sequences from `action_token` ordered by `step_index` first.
